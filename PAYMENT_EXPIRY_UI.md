# Платёжный срок и очистка UI

Текущий выпуск — [PERSONALIZATION_RELEASE.md](PERSONALIZATION_RELEASE.md).
Серверные API/срок600 секунд/цены/скидки/идемпотентность не меняются.
Production backend e6bb6d… уже поддерживает expires_at/server_time и позднюю
оплату. Повторная установка серверных патчей не требуется.

## Жизненный цикл

1. Выбор тарифа показывает «Оплатить»; chooser не создаёт заказ.
2. Только выбор провайдера вызывает POST с устойчивым ключом.
3. Полученный expires_at отсчитывается по server_time, без сброса при reload.
   Pending восстанавливается без автоматически выбранного тарифа/CTA.
4. Native cancelled скрывает карточку/таймер/progress/CTA. Это локальное
   закрытие, серверный заказ и его ключ не удаляются и не объявляются canceled.
5. Локальный ноль делает только GET и показывает «Проверяем оплату».
6. Подтверждённый expired показывает один toast, затем убирает карточку,
   закрывает chooser и сбрасывает выбор. Старые expired не возвращаются.
7. Подтверждённый paid показывает один success toast, обновляет профиль
   из backend и очищает временный UI. Client paid не выдаёт подписку.

## История и повтор

Невидимые ID остаются в paymentOrderHistory для фоновой сверки. uiHidden
отделяет видимость от финансового статуса, notices дедуплицирует уведомления.
trackedPaymentOrders сохраняет скрытые незавершённые заказы; render не выводит
их. Проверяется вся очередь с concurrency3 и single-flight, без нового POST.
Поздний paid старого ID не удаляет новую попытку. Устаревший pending не
возвращает оплаченный заказ в видимый UI.

Повтор после отмены требует снова выбрать тариф и использует прежний ключ.
После expiry перед новым ключом проверяется старый заказ, обновляется bootstrap;
изменённую цену пользователь подтверждает отдельным нажатием. UI очистка
не освобождает coupon hold и не меняет старую цену на сервере.

Все ответы проверяются по ID/провайдеру/валюте/сумме. В storage нет initData,
quote_token, секретов или invoice/confirmation URL; история разделена по owner.
Просроченная серверная запись остаётся для сверки/возврата/идемпотентности.
При ручном удалении browser storage может восстановиться серверный pending,
поскольку локальное скрытие не является отменой у провайдера.

## Внешние ограничения

Stars не имеет TTL invoice, а используемый redirect checkout ЮKassa —
merchant-set TTL10 минут. Backend отклоняет новый Stars pre-checkout после
срока и продолжает обслуживать проверенные поздние списания ровно один раз.
Эти серверные правила текущим frontend-выпуском не меняются.
Коэффициент1 ⭐ =2 ₽ сохранён, ЮKassa остаётся выключенной.

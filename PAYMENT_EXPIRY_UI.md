# Таймер оплаты Mini App

## Интерфейс и восстановление

Выбор тарифа и открытие Bottom Sheet не создают счёт и не запускают таймер.
После ответа backend таймер появляется в окне оплаты и компактно в профиле:
`10:00 → 09:59 → 00:00`. Поэтому срок остаётся виден после закрытия native
Stars invoice или окна способов оплаты. Название метода и срок тарифа рядом
позволяют различить несколько заказов.

Источники срока — серверные `created_at`, `expires_at`, `server_time`.
Разница серверного и клиентского времени учитывается; повторный вход,
перезагрузка, закрытие счёта и выбор другого тарифа срок не обновляют.
Bootstrap восстанавливает незавершённые Stars- и RUB-заказы владельца,
в том числе после очистки localStorage. Старый API без дат продолжает работать
без вымышленного локального десятиминутного срока.

Последние 60 секунд имеют мягкую янтарную подсветку. Резкого мигания и
бесконечной анимации нет; цифры имеют одинаковую ширину. Изменение цифр
не заменяет DOM-кнопку и не теряет клавиатурный фокус. Секундные обновления
не объявляются screen reader каждую секунду.

## Истечение и новые заказы

После срока показано «Время оплаты истекло» и предложение создать новый счёт.
На достижении нуля выполняется только GET старого заказа, без нового POST.
По явному нажатию способа оплаты сначала повторно проверяется старый заказ,
обновляется bootstrap и только затем может появиться новый Idempotency-Key.
При ошибке проверки новый заказ не создаётся.

Если обновлённая цена отличается от прежнего счёта, приложение показывает
её и требует ещё одно явное нажатие. Это относится, например, к скидке,
удерживаемой за старым потенциально оплачиваемым заказом. `discount_pending`
показывает короткое пояснение. Приложение не выставляет полную цену по клику
на старую льготную сумму.

Несекретная история прежних ID сохраняется, поэтому позднюю оплату можно
проверить отдельно. Подтверждение старого счёта не удаляет новую попытку.
Статусы paid/refunded имеют приоритет над локальным истечением; фактическая
подписка всегда обновляется из backend, а не по клиентскому событию paid.
GET-ответы проверяются по ID, провайдеру, валюте и сумме.
Восстановление проходит всю историю с максимум тремя одновременными GET;
повторный focus во время проверки использует ту же задачу. Старые истёкшие
записи не задерживают проверку остальных и не создают новые платежи.

В localStorage сохраняются ID/UUID попытки, исходная цена, статус, время
создания/окончания и поправка часов, раздельно для Telegram-пользователя.
Confirmation/invoice URL, initData, quote_token и секреты туда не записываются.

## Ограничения и установка

Таймер ограничивает checkout на сервере. Stars не предоставляет TTL invoice;
текущий redirect API ЮKassa не позволяет задать магазином ровно десять минут.
Внешняя ссылка не объявляется отменённой у провайдера. Проверенная поздняя
оплата начисляется backend ровно один раз. Политика финансовых состояний,
удержания скидки и очереди бота — в PAYMENT_EXPIRY.md серверного PR.

Для полного таймера требуется backend PR
[SOL_VPN_SERVER #7](https://github.com/vorotninegor-png/SOL_VPN_SERVER/pull/7).
Подготовленный backend состоит из четырёх файлов: server.py из подтверждённого
текущего исходника, unified_payments.py, admin_vip.py и payment_deadlines.py.
Действующий установленный stars_payments.py не заменяется.
Порядок установки/backup/отката — [UPDATE_GUIDE.md](UPDATE_GUIDE.md).

```sh
node --check app.js
node tests/payment-expiry.cjs
node tests/payment-methods.cjs
node tests/stars-checkout.cjs
```

Сценарии `payment-expiry.cjs` — **12 проверок** с искусственными часами и локальным API. Проверяются отсутствие
таймера/POST до создания, шестичасовой сдвиг часов, повторный вход, ноль,
янтарное состояние, GET перед новым счётом, позднее подтверждение старого ID,
скидки, одновременное восстановление Stars/ЮKassa, изоляция владельца,
подмена данных Stars POST/poll и очередь из девяти старых заказов.
Настоящие платежи, сообщения и внешние страницы не вызываются.
Реальный Telegram на Android/iOS и sandbox провайдеров требуют отдельной проверки.

ЮKassa в production не включалась, FirstVDS не обновлялся, PR не объединялись.

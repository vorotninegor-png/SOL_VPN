## Настройки → Оформление

Вход — «Кабинет → Настройки». Все изменения применяются к настоящим экранам
сразу; отдельного preview и кнопки «Применить» нет.

- Темы: Cosmic (по умолчанию), Classic Dark/Light, Deep Ocean, Aurora, Solar,
  Matrix. Matrix получает статическую сетку и терминальные акценты.
- Фон: звёзды/чистый фон, интенсивность, градиенты.
- Плашки: Glass/Solid/Outline, углы 0–32 px, непрозрачность 35–100%, тень.
- Кнопки: сплошные, контурные, неоновые, стеклянные; углы, подсветка, реакция.
- Свечение: включение, интенсивность 0–100%. При нуле контраст сохраняется.
- Анимации: включение, скорость, Smooth Blend / Radial Wave / Liquid Morph.

Палитры ограничены согласованными цветами текста/поверхностей/акцентов.
Генератор не выбирает произвольный RGB: сохраняются контраст и функциональные
цвета ошибок/успеха. VIP остаётся золотым/фиолетовым во всех темах.
Светлая тема отдельно проверяет реальные подписи, выбранный FAQ и поля админки.

Liquid Morph — стандартный переход. Снимки создаются только на смене палитры,
применении пресета/генерации/сбросе; перемещение ползунков их не запускает.
Постоянного canvas/render-loop нет. При отсутствии View Transitions или малой
мощности устройства применяется Smooth Blend; reduced motion и выключенные
анимации дают непосредственное применение. На слабых устройствах также
упрощено размытие карточек. Декоративная анимация не требуется для оплаты
или выдачи конфигурации. Техническая основа:
[Document.startViewTransition](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition).

## Постоянный режим, генератор и пресеты

Режим «Постоянное» сохраняет выбранные параметры. «Сгенерировать и оставить»
выбирает совместимую комбинацию и делает её постоянной. «Случайное при запуске»
генерирует один раз при новом документе Mini App, до показа интерфейса.
Вкладки, focus/visibility и обычное обновление bootstrap оформление не меняют.
Нажатие «Случайное оформление» создаёт другую комбинацию в текущем режиме.

«Мои оформления» хранит до 20 именованных пресетов: сохранить, применить,
удалить. Имена вставляются через textContent. Применение/сохранение пресета
не выключает случайный режим запуска. Сброс возвращает Cosmic и все стандартные
параметры, включая Liquid Morph, сохраняя пресеты.

Хранилище: `sol-appearance:v1:TELEGRAM_ID` в localStorage, отдельно для каждого
пользователя на устройстве. Формат: version/settings/presets. Проверяются
enum, boolean, числовые пределы, ID/имена пресетов, лимит и дубликаты.
При недоступном хранилище настройки продолжают работать в памяти текущего сеанса
с понятным статусом. Удаление данных браузера удалит локальные оформления;
синхронизации между устройствами и новых миграций нет.

Для ранней косметической загрузки используется ID из Telegram SDK; он не
авторизует API. Затем identity заменяется подтверждённым bootstrap ID.
Если ID до bootstrap неизвестен, основной интерфейс скрыт до выбора правильной
палитры: вспышки стандартной темы нет. Настройки не содержат initData, токенов,
VPN-ключей, платёжных ссылок и не отправляются другим пользователям.

## Платёжный UI и финансовые записи

Bottom Sheet на обычном экране занимает минимум около 50% доступной высоты,
сохраняет фиолетовую обводку, blur 7 px и переход 330 ms. На малой высоте есть
внутренняя прокрутка и safe-area; VisualViewport учитывает уменьшение экрана
при клавиатуре.

Восстановление pending-заказа показывает его исходный таймер, но **не выбирает
тариф и не показывает «Оплатить» автоматически**. Выбор требуется явно.
Обычное закрытие chooser очищает выбор и временные сообщения, не создавая счёт.

После Telegram cancellation скрываются карточка, таймер, CTA и progress.
Серверный заказ остаётся pending/confirming, ключ попытки сохраняется для
безопасного повтора. Это не отмена платежа у провайдера.

Локальный ноль запускает только GET; до ответа показано «00:00 · Проверяем
оплату». Только подтверждённый expired даёт одно уведомление, затем карточка
плавно исчезает и выбор очищается. При повторном входе старые expired не
возвращаются. Проверенный paid даёт одно уведомление, закрывает sheet,
очищает временный UI и обновляет профиль из backend.

`paymentOrderHistory` хранит только идентификаторы/цену/состояние и признаки
`uiHidden`, `notices`. `trackedPaymentOrders` продолжает финансовую сверку
скрытых незавершённых заказов, а render фильтрует их из видимого UI.
Один заказ не создаёт несколько одинаковых уведомлений. Поздняя оплата старого
заказа не удаляет новую попытку; stale pending не возвращает уже подтверждённый
paid. История backend, выдача, скидки, идемпотентность и возвраты не меняются.
Платёжный обработчик завершает обновление bootstrap до снятия своей блокировки;
GET fallback проверен также с задержанным ответом профиля.
**1 ⭐ = 2 ₽**, серверные цены и срок 600 секунд сохранены. ЮKassa выключена.

## Все VIP

Цвет кнопки и aria-pressed теперь определяются реальным `isVip`.
Операция по нажатию по-прежнему управляет только `vip_admin_granted`:
защищённое/купленное/старое право не отзывается. Поэтому кнопка защищённого
VIP остаётся золотой после снятия административного гранта. Подпись объясняет
источник; отсутствие нового metadata отключает небезопасное действие.

«Все VIP» отдельно читает существующий `/api/admin/users` постранично по 100,
поскольку прежний approved_users содержит только административные гранты.
Это чтение не меняет поиск, страницы, черновики и scroll основного списка.
ID дедуплицируются; версии защищают от устаревших ответов во время VIP-запроса.
Ручное обновление принимает новые состояния backend, не затирая их старым кэшем.
На старом API без признака полноты показывается соответствующий статус.
Серверная проверка прав остаётся прежней; обычные пользователи API не получают.

## FAQ

Третий вопрос: «Где купить Telegram Stars?». Точный новый ответ:
«Мы подобрали сервис для покупки Telegram Stars. Перед покупкой сравните условия.»
Одна кнопка «Перейти», точный URL
`https://t.me/HelperStars_Robot?start=8544752152`.
Второй сервис и его флаг исключены из кода UI; даже старый включённый флаг
не возвращает ссылку. Необязательные настоящие рекламные сведения остаются
в SOL_FAQ_STARS_AD_INFO. Перед публикацией проверить применимые условия;
идентификаторы/обещания не выдуманы.

Волна текста и reset при повторном входе сохранены. Кнопка — отдельный DOM,
Y18/blur2, подъём 400 ms. Пауза 300 ms даёт высоте терминала место для одной
кнопки и предотвращает обрезание в промежуточных кадрах.

## Безопасная публикация и откат — после отдельного разрешения

1. Сохранить опубликованный frontend и его commit: index.html, app.js,
   style.css, действующий config.js и остальные текущие assets. Backend/БД
   для этого frontend-обновления не менять и прежние серверные патчи не запускать.
2. Проверить эту ветку локально с mock API и полный diff. config.js не включён
   в PR, его API URL сохраняется; config.example.js не копировать поверх него.
3. После разрешения разместить appearance.js, appearance.css, app.js и
   index.html как один согласованный выпуск. Базовый style.css должен оставаться
   доступным; его содержимое прежнее, query-version ресурсов — 5008.
   На файловом хостинге сначала новые assets, index.html последним;
   предпочтительна атомарная смена release. В GitHub Pages публикация только
   после отдельно согласованного merge/действия владельца.
4. Проверить вход разных аккаунтов, восстановление оформления, три режима,
   Classic Light, FAQ, native CTA и отмену без покупки. Админские проверки
   реальных пользователей выполнять без изменения прав. Не включать ЮKassa.
5. Для отката вернуть весь предыдущий комплект frontend, включая index,
   сохранив рабочий config.js. Backend и текущую БД не восстанавливать.
   Новые ключи localStorage можно оставить: предыдущий frontend их игнорирует,
   после forward-fix настройки вернутся. Старый UI может снова показывать
   прежние статусы/выбор тарифа; это не повторная оплата, backend остаётся
   авторитетным и защищает от двойного начисления.

Ничего не объединено и не опубликовано автоматически. На FirstVDS не выполнялись
установка, migration/backup production-БД, остановка или перезапуск служб.

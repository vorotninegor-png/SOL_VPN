# Обновление оплаты, FAQ и VIP

Карточки показывают только рубли. Единая нижняя кнопка «Оплатить» открывает
Bottom Sheet без создания заказа; Stars создаёт invoice только после выбора.
ЮKassa отправляет кнопку оплаты в чат бота и предлагает безопасный ручной
fallback к тому же заказу при недоставке. Цена старого счёта явно помечается,
закрытый sheet не вызывает отложенного перехода в браузер.

Оба способа получают 10-минутный срок от создания заказа на сервере.
Обратный отсчёт восстанавливается после повторного входа, последние 60 секунд
подсвечены мягким янтарным цветом. После истечения старый заказ проверяется
перед явным созданием нового. Подтверждённые поздние платежи начисляются один
раз; ограничения срока внешних ссылок описаны в PAYMENT_EXPIRY_UI.md и
PAYMENT_EXPIRY.md серверного PR.

В FAQ девять вопросов: покупка Stars — третья, строки вариантов поднимаются
Liquid Rise; возврат в «Инфо» сбрасывает ответ. Второй сервис по умолчанию
выключен. Перед публикацией требуется проверка условий/рекламных сведений.
В карточках пользователей появилась VIP-кнопка по ID с сохранением независимых
прав. Админские декоративные эмодзи заменены белыми неоновыми SVG.
Ресурсы — 5007. Установка/откат и ограничения — UPDATE_GUIDE.md.

ЮKassa не включается автоматически; live Stars и коэффициент 2 ₽/⭐ сохранены.
Старый сервер GitHub не заменяет действующий FirstVDS. Перед включением
ЮKassa нужны магазин, фискализация и проверка правил цифровых платежей Telegram.

# Mini App: «Админ → Все пользователи» и «Инфо»

Ветка создана от актуальной `main`, без слияния или изменения PR №2.
Его решения проверены: полезны единый стиль SVG и градиент у края списка;
измерение высоты только при замене текста не покрывает смену ширины/шрифтов,
а сброс ответа при каждом входе расходится с сохранением выбранного вопроса.
Новая реализация измеряет контент через ResizeObserver, отменяет анимации
и сохраняет выбор. Она не требует применения PR №2 или старого PR №1.

## Изменения

- `app.js`: постраничная загрузка защищённого API, серверный поиск с отменой
  устаревших запросов, устранение дублей, сохранение поиска/прокрутки/черновиков,
  кнопки профиля и сообщения, посимвольный FAQ с reduced motion.
- `index.html`: интерфейс карточек/поиска/статуса, восемь SVG, доступный терминал;
  версии статических ресурсов `5003`.
- `style.css`: локальные стили двух разделов, подсветка 380 мс, высота 420 мс,
  градиент вне ответа, мобильная компоновка.
- `tests/info-faq.cjs`, `tests/admin-users.cjs`, `tests/README.md`: автономные
  браузерные проверки без настоящих пользователей, платежей и VPN.

Содержание FAQ взято из `main`: убраны эмодзи, исправлены название кнопки
«Копировать» и описание получения ключа. Обещания 1 Гбит/с и десяти устройств
из старого ТЗ не добавлялись: в коде репозитория они не подтверждены.

## API и совместимость

`GET /api/admin/users?limit=50&offset=0&q=...` использует существующую проверку
Telegram initData на сервере. Новый ответ содержит `users`, `pagination`
(`total`, `next_offset`, `has_more`) и `capabilities` (`profile_link`,
`contact_message`). Поиск выполняется по всей базе, а не по видимой странице.
Старый ответ без pagination также отображается, с локальными страницами и
предупреждением: полнота списка не подтверждена. Это не замена серверной пагинации.

Для ссылки без username нужен `POST /api/admin/users/{id}/profile-link`,
для сообщения — `POST /api/admin/users/{id}/message` с `{ "text": "..." }`.
При отсутствии этих возможностей интерфейс честно сообщает о недоступности.
Отправка требует отдельного нажатия администратора, проверяется сервером
и не предоставляет доступ к API обычным пользователям.

## Ограничения Telegram

- Для username используется `https://t.me/<username>?profile` через
  [openTelegramLink](https://core.telegram.org/bots/webapps#initializing-mini-apps).
  SDK не сообщает, открылся ли профиль; интерфейс не утверждает успех.
- [`tg://user?id=...`](https://core.telegram.org/api/links#id-links) — конструкция
  Bot API, не универсальная ссылка из WebView. Для пользователя без username
  кнопка в Mini App запрашивает единственную ссылку в личный чат администратора
  с SOL VPN. Затем администратор нажимает нативную кнопку Telegram. Список и
  поиск остаются в Mini App. Дополнительное нажатие неизбежно для этого способа.
- Приватность может запретить выдачу/открытие ссылки. Показана ошибка,
  доступна альтернатива через бота; обход ограничений не используется.
- Наличие записи в SQLite не доказывает разрешение на сообщения. Bot API
  запрещает начинать переписку с пользователем без его согласия; блокировка
  бота и отсутствие разрешения возвращают понятную ошибку. Подтверждение API
  означает приём сообщения Telegram, а не прочтение адресатом.
- Android/iOS проверены только по размерам в браузере. Telegram Desktop
  обнаружен на рабочем компьютере; новая сборка не установлена в настоящий
  Mini App, поэтому реальные переходы в этих трёх клиентах не подтверждены.

## Проверки

12 браузерных сценариев FAQ и 13 админских сценариев в Chrome 156.
Ширины 280–768 px, альбомная ориентация, быстрые переключения, reduced motion,
все восемь ответов; ошибок JavaScript нет. Серверные HTTP-проверки и существующие
smoke-тесты выполняются в отдельном backend PR. Реальные оплаты, XHTTP и VPN
не запускались. Регрессия в production этими локальными проверками не исключена.

## Обновление и откат (после отдельного подтверждения)

1. Сначала сверить точечный backend PR с действующим
   `/opt/sol-vpn-release-75f5fab/server.py`. Его версия содержит XHTTP и ЮKassa,
   которых нет в GitHub. Нельзя заменять его полным `server.py` из репозитория.
   Для окончательной проверки нужен исходник действующего файла без секретов.
2. После согласования подготовить тестовую копию текущего release и применить
   только совместимые API-изменения. Не изменять `.env`, Xray config и SQLite.
   Проверить защищённые маршруты и штатные платежи/VPN в тестовой среде.
3. Сохранить предыдущие статические `app.js`, `index.html`, `style.css` и после
   проверки установить только эти три файла из нового коммита. Сохранить
   действующий `config.js`, очистить кеш Mini App и проверить авторизацию.
4. При проблеме вернуть предыдущие три статических файла вместе с их версиями
   ресурсов. Новые API совместимы со старым клиентом; откат frontend не требует
   отката БД. Если откатывается backend, вернуть сохранённый рабочий release,
   а не версию GitHub, и отдельно проверить `sol-vpn.service`.

Слияние PR, установка на FirstVDS и перезапуск службы автоматически не выполняются.

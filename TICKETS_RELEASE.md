# SOL VPN — тикеты в Mini App, этап 2

Это отдельный frontend-выпуск после принятия Python-бота из серверного ticket PR.
Одновременная установка двух обновлений не требуется. Новая тема Cosmic/фон
в этот выпуск не входят; существующие темы и настройки сохранены.

## Что изменилось

- FAQ: SVG-кнопка поддержки между терминалом и вопросами. Полноэкранная панель
  раскрывается от кнопки и сворачивается обратно, не сдвигая FAQ. Учитываются
  reduced motion, safe area, маленький экран, клавиатура и кнопка «Назад» Telegram.
- Список собственных активных тикетов; создание с темой, описанием и десятью
  файлами. Номер выдаёт сервер. Пустая форма серая, заполненная — зелёная.
  «Назад» отменяет черновик; при сбое сети отмена повторяется при следующем входе.
- Чат с датами, текстом, фото/видео/документами. Сначала загружаются последние
  сообщения, более ранние — при прокрутке вверх. Новые ответы не сбрасывают
  позицию читателя. Повтор запроса после потери ответа использует тот же UUID.
- Ответы Python-бота и Mini App имеют общие номера, историю и статус. Опрос раз
  в четыре секунды только в открытом приложении. Непрочитанное выделяется;
  своя запись из другого канала обновляет экран без лишнего уведомления.
- Админка: вкладки «Панель»/«Тикеты» со сдвигом в стороны. Существующий DOM,
  значения полей и прокрутка основной панели сохраняются. Тикеты сгруппированы
  по постоянному номеру пользователя; полное имя ведёт в Telegram. Зелёная SVG
  открывает чат, красная — подтверждение закрытия. Проверку прав выполняет API.

Курс Stars, платежи, VPN-ключи, подписки, VIP и рассылка не изменяются.
Файлы app.js/index.html изменены только в местах подключения панели/навигации
и скрытия платёжной CTA на время поддержки. style.css, appearance.* и miniapp-ui.*
не меняются. Новые ресурсы support.js/support.css, версия загрузки 5010.

## Авторизация и файлы

Используется прежний apiFetch с подписанным Telegram initData. Клиент не отправляет
user_id/is_admin и не может назначать номера. Админ-доступ только у 8544752152;
сервер заново проверяет владельца тикета/права на каждом запросе. Данные и Blob URL
удаляются при смене аккаунта. localStorage содержит только ID отменяемых черновиков
отдельно по аккаунту, без текста переписки, токенов или Telegram file_id.

Контракт описан в серверном TICKET_API.md: /api/support/* и /api/admin/support/*.
Файлы загружаются с авторизацией, максимум 10 МБ фото и 20 МБ видео/документ.
Telegram Bot API не имеет upload-only метода: backend временно отправляет файл
самому авторизованному загрузившему и пытается удалить служебное сообщение после
сохранения. До «Отправить» второй стороне файл не передаётся. Пользователь должен
предварительно открыть бота и нажать /start. Неопределённая загрузка не повторяется
автоматически: её можно удалить и загрузить заново. Непосланные файлы чата
восстанавливаются после повторного входа. Скачать/просмотреть файл можно только
через защищённый endpoint, Bot API URL/токен в браузер не поступают.

## Последовательность будущей установки

Эти действия не выполнены на FirstVDS. Никакого автоматического merge/deploy нет.

1. Проверить и принять Python-бота по серверному TICKETS.md. Сначала серверный
   SOL_TICKETS_ENABLED=1, SOL_TICKET_API_ENABLED=0, клиентский флаг выключен.
   Проверить создание/отмену, ответы, калькулятор, архив, админку и прежние функции.
2. После отдельного согласования включить SOL_TICKET_API_ENABLED=1 в действующем
   окружении сервера. Разрешённый оператором перезапуск — по серверной инструкции.
   Миграция уже выполнена на первом этапе: повторно применять старые патчи не нужно.
3. Сохранить приватную резервную копию **текущего frontend**, включая config.js и
   index.html/app.js. Зафиксировать исходный commit/способ публикации. Не публиковать
   config.js, резервные копии и локальные файлы пользователя в репозитории.
4. Выпустить этот PR обычным способом размещения Mini App. Доставить app.js,
   index.html, support.js, support.css вместе. Прежние appearance.* / miniapp-ui.* /
   style.css также должны оставаться доступны. Сохранить действующий config.js:
   шаблон config.example.js поверх него не копировать.
5. После публикации и проверки API добавить в **текущий** приватный config.js:

   ```js
   window.SOL_SUPPORT_ENABLED = true;
   ```

   Без этого флага поддержка не показывает новые элементы и не делает ticket-запросы.
   При backend flag off кнопки остаются скрытыми; прежняя навигация работает.
6. Обновить Mini App полностью, проверить загрузку ресурсов 5010 без старого cache,
   два согласованных тестовых аккаунта и настоящие Android/iOS Telegram: FAQ,
   клавиатура/Назад, тема Light/Dark, создание/отмена, файлы, ответ из обоих каналов,
   непрочитанные, подтверждение закрытия, исходная админка. У обычного пользователя
   нет админ-вкладки. Ссылка профиля зависит от приватности Telegram.

Проверить связь на уже существующем тестовом тикете после повторного открытия.
Реальные покупки и массовую рассылку для приёмки не запускать. ЮKassa не включать.

## Откат

Сначала поставить window.SOL_SUPPORT_ENABLED=false в текущем config.js и обновить
Mini App. Если нужно, вернуть **согласованный предыдущий frontend целиком** из
защищённой копии. Не восстанавливать старый config.js поверх изменившегося API URL.
Данные тикетов остаются на сервере; Python-бот продолжает работать. Серверный API
можно выключить отдельно по его инструкции без удаления таблиц/истории.
Backend server.py/SQLite/платежи этим frontend-откатом не заменяются.

## Локальные проверки

```sh
node --check app.js
node --check support.js
node tests/appearance.cjs
node tests/payment-cleanup.cjs
node tests/payment-methods.cjs
node tests/stars-checkout.cjs
node tests/payment-expiry.cjs
node tests/admin-users.cjs
node tests/info-faq.cjs
node tests/miniapp-ui.cjs
node tests/support.cjs
```

155 browser checks: 132 прежние и 23 новых. Новый suite проверяет выключенный флаг,
ACL/смену аккаунта, отсутствие XSS, форму/файлы/отмену, повтор UUID после сетевой
неопределённости, историю/пагинацию/прокрутку, unread/hidden, межканальную запись,
перезагрузку, сохранность админки, доступность, шесть тем и ширины 320–1024 px.
Моки блокируют внешнюю сеть; сообщений/платежей production нет.

Дополнительно из backend-checkout запускается tests/run_ticket_browser_bridge.py
с --release-dir проверенной копии PR8 и --frontend-root этого checkout. Три сквозных
сценария используют настоящий FastAPI, HMAC initData и dispatcher, искусственную
SQLite и fake Telegram: создание с файлом/ответ админа, ответ Python-бота в той же
истории, закрытие с журналом доставки. В production test-only routes не добавляются.

Физические Telegram Android/iOS, реальные загрузки Telegram и FirstVDS/systemd
ещё требуют отдельной приёмки. Скриншоты и браузерные проверки не заменяют её.

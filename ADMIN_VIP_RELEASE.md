# VIP: эффективный статус и безопасное управление источником

Золотой цвет/свечение и aria-pressed отражают `isVip`, включая старые,
защищённые и купленные права. При `isVip=false` кнопка фиолетовая. Цвета
сохраняются во всех темах; белые SVG и функциональные цвета остаются различимыми.

Действие использует существующий POST /api/admin/vip по числовому user_id
и явному enabled. Переключается только `vip_admin_granted`, а не весь
эффективный VIP. Снятие административного гранта защищённого VIP оставляет
кнопку золотой; пояснение сообщает, что другое право сохранено. Оплаченные
месяцы, ключи и серверные источники не меняются. При отсутствии metadata
старого API небезопасное действие отключено.

«Все VIP» загружается отдельным чтением /api/admin/users по100 на страницу.
Прежний approved_users покрывает лишь назначенные администратором права и
не используется как единственный источник полного списка. ID дедуплицируются,
все действующие VIP перечисляются, защищённые права имеют неактивное удаление.
Неполный ответ старого API отмечается явно. Есть ручное обновление.

Ревизии и версии защищают от ответов, устаревших во время изменения VIP.
Свежий backend-ответ при обновлении заменяет старый кэш прав. Отдельная
загрузка не сбрасывает поиск, страницы, scroll, drawers и черновики общего
списка. При смене identity прежние данные очищаются; права на каждом API
по-прежнему проверяет backend.

Backend с установленным SHA e6bb6d… уже предоставляет необходимые поля;
изменения сервера и миграции для этого frontend-выпуска не нужны.

Проверки: `tests/admin-users.cjs` — 19 сценариев, дополнительные проверки
полного VIP-списка за пределами первой страницы/внешнего изменения прав —
`tests/payment-cleanup.cjs`. Все пользователи и действия искусственные;
реальные права/подписки в тестах не меняются.
